# I2RT YAM linear gripper — STEP files

This directory also contains HIWIN MG-series linear guide models; see
[the second section](#hiwin-mg-series-linear-guides--step-files) below.

STEP (AP214) solid models of the I2RT [linear gripper](https://i2rt.com/products/yam-gripper-1)
("Linear 4310") for the YAM arm.

| File | Contents |
| --- | --- |
| `gripper.step` | Gripper body (motor + housing + linear rails), 1 solid |
| `tip_left.step` | Left finger + carriage, 1 solid |
| `tip_right.step` | Right finger + carriage, 1 solid |
| `linear_gripper_assembly.step` | All three parts posed per the MuJoCo model at joint position 0 (closed), origin at the gripper mount frame, tool axis pointing −z |

Units are **millimeters**.

## Provenance and caveats

I2RT does not publish B-rep CAD for this gripper. These files were generated
from the STL meshes in the MIT-licensed
[i2rt-robotics/i2rt](https://github.com/i2rt-robotics/i2rt) repository
(commit `1276f63d640eb45c226efd3dc08430b810372e94`, path
`i2rt/robot_models/gripper/linear_4310/assets/`), which are themselves
decimated visual meshes (8,000 triangles per part).

Consequences:

- **Curved surfaces are faceted.** Planar regions were merged into clean
  planar faces (`ShapeUpgrade_UnifySameDomain`), but cylinders/fillets remain
  polygonal. Fine for mounting fixtures, clearance checks, and visualization;
  not a parametric model.
- Solids are watertight and volume-exact against the source meshes
  (relative error < 1e-8), including the two internal cavities in each
  finger, which are represented as true voids.
- Individual part files keep their original STL mesh frames; use the
  assembly file for correctly posed geometry.

## Regenerating

```bash
pip install trimesh scipy cadquery-ocp
git clone https://github.com/i2rt-robotics/i2rt.git
python stl_to_step.py ./i2rt
```

`stl_to_step.py` sews each STL into a closed shell, converts it to a solid,
boolean-subtracts internal cavities, merges coplanar facets, and writes STEP.
It asserts volume parity with the source mesh at every stage.

# HIWIN MG-series linear guides — STEP files

Parametric B-rep models (true solids, not mesh conversions) of HIWIN
miniature linear guide components, generated by `hiwin_mg_step.py`.
Units are **millimeters**.

| File | Contents |
| --- | --- |
| `MGN7R_100mm.step` | MGN7 narrow rail, 100 mm (standard length: 7 holes at 15 mm pitch, 5 mm end offsets) |
| `MGW7R_100mm.step` | MGW7 wide rail, 100 mm (non-standard length for this series; 3 holes at 30 mm pitch, symmetric 20 mm end offsets) |
| `MGN7C.step` | MGN7C compact carriage (22.5 × 17 × H8, 4×M2×2.5 on 8×12) |
| `MGN7H.step` | MGN7H long carriage (30.8 × 17 × H8, 4×M2×2.5 on 13×12) |
| `MGW7C.step` | MGW7C compact carriage (31.2 × 25 × H9, 4×M3×3 on 10×19) |
| `MGW7H.step` | MGW7H long carriage (41 × 25 × H9, 4×M3×3 on 19×19) |

**Series compatibility:** MGN7 carriages run only on MGN7 rail (7 mm
wide) and MGW7 carriages only on MGW7 rail (14 mm wide) — an MGW7H
carriage does not fit an MGN7 rail, which is why both rails are included.

## Coordinate convention

Rails and carriages share an assembly frame so they drop together
directly: rail axis = +X with the rail bottom face at z=0 (origin at one
end, centered in Y); carriages are centered in X/Y at their block center
and span z ∈ [H1, H] — i.e. a carriage placed over a rail at z=0 sits at
ride height with correct groove engagement (verified: zero boolean
interference for all four rail/carriage pairings).

## Dimensions and simplifications

All catalog dimensions are from the official HIWIN MG Series catalog
(G99TE24-2410, pp. 88–89): assembly H/H1, block W/B/C/L1/L, thread size
and depth, rail WR/HR, counterbore D×h/d, pitch P, end offset E.

Simplifications (documented in the script): ball raceway grooves and the
mating ridges are circular arcs (the true gothic-arch profile is
proprietary and undocumented); thread holes are nominal-diameter plain
holes; end caps are modeled as inset extensions of the body without
seal/recirculation detail; no edge chamfers. Suitable for fixtures,
clearance checks, and rendering — not raceway analysis.

## Regenerating

```bash
pip install build123d
python hiwin_mg_step.py   # writes the six .step files to the CWD
```
